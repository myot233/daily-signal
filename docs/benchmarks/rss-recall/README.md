# RSS 日报召回率 benchmark

一个小型精选日报评测：16 条固定 RSS 摘要，8 个应入选事件，2 条重复报道，6 条干扰内容。数据为**人工编写的合成场景**，项目名和数字均用于测试，不是真实新闻。初始标注由编写者给出，尚未经独立人工复核。

## 指标

**召回率 = 日报中出现的应入选事件数 / 8。** 同一事件的任意来源进入最终卡片即算命中，多来源和重复卡片只算一次。同时给出事件精确率（命中的应入选事件 / 所有入选事件）、`missed` 漏召回清单和 `unexpected` 误选清单。空结果两项指标均记为 0。

只读 `curation.cards[].sourceIds`，不使用归档中的 `sources`：后者包含所有输入文章，不能代表实际入选。未知来源 ID、错误的数据集 ID 或缺少卡片字段会报错。

## 验收基线

`baseline.json` 固定这份数据集的初始验收标准，三项必须同时满足：

| 指标       | 门槛    | 含义                                               |
| ---------- | ------- | -------------------------------------------------- |
| 事件召回率 | ≥ 87.5% | 8 个应入选事件至少召回 7 个，最多漏掉 1 个         |
| 事件精确率 | ≥ 80%   | 限制误选；例如召回全部 8 个时最多混入 2 个干扰事件 |
| 卡片数     | ≤ 10    | 与固定输入的输出预算一致，重复卡片同样占用预算     |

这是**人工设定的验收门槛，不是模型实测基线**：小样本允许一次遗漏，用精确率和条数限制防止全部选入。它尚未经真实模型或独立标注验证，不能代表统计显著的质量目标。结果中的 `baseline.checks` 指出失败项，`baseline.passed` 表示是否全部达标。修改门槛时应保留版本记录，不随某次模型结果调低门槛。

每次运行单独验收；发布前若重复 3 次，要求 3 次分别达标，保留全部输出，不只挑最好一次。指标只衡量来源覆盖，仍需抽查卡片是否真正讲述对应事件。

## 运行

在仓库根目录执行：

```sh
# 离线演示计分器，不请求模型
pnpm benchmark:recall

# 对一次生成结果重新计分（相对路径以仓库根目录为准）
pnpm benchmark:recall /tmp/rss-result.json

# 验收基线：达标退出 0，未达标退出 1
pnpm benchmark:recall /tmp/rss-result.json --check
```

默认读取 `example-result.json`，输出 `kind: "example"`，召回率为 **6/8 = 75%**，精确率为 **6/7 ≈ 85.7%**，遗漏 r13、r15，误选 r02。这只是演示数据，不能当作真实模型成绩。

示例未达到召回率基线；普通评分仍退出 0，加上 `--check` 则退出 1。真实模型生成若未达标，也会保留 `--out` 结果，便于检查遗漏原因。

需要测真实模型时，将连接配置保存在仓库外的私有文件，例如 `/tmp/rss-connection.json`（文件权限设为 `600`，用后删除）：

```json
{
  "baseUrl": "https://your-provider.example/v1",
  "model": "your-model-id",
  "deepseekThinking": "disabled",
  "apiKey": "your-api-key"
}
```

```sh
pnpm benchmark:recall --generate --check --out /tmp/rss-result.json < /tmp/rss-connection.json
```

该命令会调用真实模型，可能产生费用；必须显式传入 `--generate`。支持 OpenAI Chat Completions 兼容接口，沿用应用的网络安全限制。配置从标准输入读取，不读取日常应用的模型凭据；每次使用独立内存数据库与冷缓存，复用生产 `generateDigest` 的筛选、去重、归组、配额和卡片生成逻辑。参考答案只在生成结束后用于计分，不传给模型。

`--out` 保存卡片、Markdown、模型、端点、模型参数、筛选设置和运行统计，不保存密钥；已有文件不会覆盖。终端显示评分 JSON。比较不同模型或提示时使用不同输出文件；单次运行有波动，必要时重复 3 次。

也可以手工整理其他生成方式的结果，再用相同命令评分，最小格式为：

```json
{
  "benchmarkId": "rss-recall-v1",
  "kind": "manual",
  "curation": { "cards": [{ "sourceIds": ["r01", "r09"] }] }
}
```

## 样本与范围

- `input.json`：固定日期、兴趣设置及 16 条 RSS 正文；模型只看到这些输入。
- `labels.json`：每个事件的来源 ID、是否应入选及理由。覆盖发布、研究、工程复盘、开源工具，以及营销、无关内容、空泛榜单、传闻、招聘和信息不足。
- `baseline.json`：与数据集 ID 绑定的召回率、精确率和卡片数验收门槛。
- 总条数上限为 10、每标签上限为 10、分数门槛为 6。标签配额有意放宽，避免 8 个应入选事件受默认每标签 3 条的限制；这不是默认设置下的成绩。
- 关闭全文抓取，统一使用固定 RSS 内容。评测从已抓取文章开始，不测订阅抓取成功率、时间窗口过滤或长篇全文模板模式。
- 这是**基于最终来源的事件覆盖率**，不自动判断摘要是否充分陈述了事件，也不验证事实正确性或错误归组。仅有引用不能证明总结正确，需要人工抽查输出 Markdown。
- 修改正文、标注或设置时同步更新数据集 ID 和示例，避免把不同口径的结果混在一起。这个小样本适合快速发现退化，不能据此推断所有订阅上的质量。

计分和隔离生成入口的回归测试包含在 `pnpm test:server` 中。模型替身测试仅验证工程链路，不作为模型质量成绩。
