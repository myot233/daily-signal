# 精选日报

在「日报设置 → 兴趣与筛选」勾选标签，也可以添加自己的标签。开启精选模式后按下列流程生成；关闭后继续使用原来的全文模板。旧日报不会被转换或覆盖。

```
当日缓存文章 → URL / 相同正文去重 → 按兴趣标签和内容类型评分
                                           ↓
                              复用已完成的正向、负向分析
                                           ↓
                      达到门槛 → 最多 60 篇候选 → 同一事件归组
                                           ↓
                            标签配额 + 总条数上限
                                           ↓
                     获取入选事件的正文 → 短卡片 + 原文摘录
                                           ↓
                    引文匹配校验 → 代码排版 → 保存独立版本
```

## 行为与边界

- 默认标签为 AI、软件工程、开源工具；标签可自选和自定义，1–20 个，每个最多 40 字符。补充偏好用于说明关注的细节。
- 单篇分析读取已有 RSS 内容，不只依赖标题。分别评价新闻、工程实践、工具、研究和观点文章。模型返回所选标签的子集、相关性、质量分数和理由。
- 入选要求匹配至少一个标签、相关性达到门槛，并且 `0.6 × 相关性 + 0.4 × 质量` 达到门槛。该权重是初始工程取值，没有声称经过质量 benchmark 优化。
- 默认最多 10 个事件，每个标签最多 3 个。一个事件匹配多个标签时占用每个标签的配额，因此可能少于总条数上限，不强行凑数。进入全局 60 篇上限前按标签轮流取候选，减轻热门标签挤占其他兴趣的问题。
- 同一具体事件的来源归为一组；仅主题或公司相同不应合并。所有候选 ID 必须完整且唯一地出现在分组结果中。
- 只对入选事件获取网页正文，每个事件最多 2 个代表来源；抓取沿用公开网络校验、重定向校验、取消、12 秒超时和 1 MB 大小上限。Readability + linkedom 只解析文本，不执行脚本或加载子资源。正文最多保留 12,000 字符；失败、付费墙或无法提取时退回 RSS，并在界面标记订阅摘要。
- 一张卡片最多 400 字符摘要、180 字符分析和 1–4 条引文。引文必须逐字匹配模型实际收到的资料（只折叠空白）。这验证了引文存在，**不等于自动证明所有摘要结论都被引文支持**。
- 模型只返回来源 ID，链接由程序从原始文章构建。归档保存原始 RSS 快照、参与写作的正文节选、引文、标签设置和生成统计；删除订阅不影响已归档版本。
- JSON、ID 或引文校验失败最多修复一次；请求失败、输出截断不自动重试。失败不会保存新的日报，但已经完成且验证通过的单篇筛选会保留，供下次继续。没有匹配内容会明确保存为空结果，区别于分析失败。
- 缓存键包含版本、模型/端点/参数、标签、补充偏好和完整输入文章。门槛和配额变化可复用单篇分数；标签、文章或模型配置变化会重新分析。密钥不参与缓存和公开记录。
- 现有 500 篇、30 万字符和 10 分钟总时限仍生效。精简后的候选用于归组，避免把全部长文交给一次调用。卡片按事件逐项生成，保存供应商配置的输出上限。

## 验证

`server/modules/ai/curation.test.ts` 使用确定性模型响应和隔离 SQLite，覆盖筛选、URL 去重、事件归组、配额、正负缓存、输入变更、坏 ID、坏引文、空结果、取消、截断、正文抽取和归档快照。它验证工程行为，不衡量真实模型质量。

Storybook 的 `Views/TemplateView` 覆盖标签添加、选择、保存、放弃、空标签拒绝和保存失败保留草稿；`Views/Report` 覆盖证据展开、来源链接、生成统计和空结果。

## 使用自己的订阅做质量对比

1. 固定 3–7 天的 RSS 快照、模型和输出预算，提前人工选出每天值得读的条目。
2. 分别用全文模板模式和精选模式生成，隐藏方案名称后阅读评分。最好为每种方案重复 3 次，观察波动。
3. 记录前 10 条值得读的数量、重要事件遗漏数、重复事件数、抽样事实是否受原文支持，以及阅读时长。
4. 精选日报的「生成记录」提供调用次数、模型报告的输入/输出 tokens、缓存数、正文数和耗时。分别记录冷缓存与复用缓存的运行；tokens 未由模型提供时记为 0，不应用这个 0 推导免费。
5. 标签选择、门槛和候选上限必须随结果记录。不要拿不同模型或不同成本预算直接得出架构优劣结论。

本次没有调用用户的付费模型，也没有把功能测试当作质量 benchmark。收藏反馈、跨日期事件记忆、独立语义事实核验和联网深度研究不属于此版本。

设计参考：[Horizon](https://github.com/Thysrael/Horizon)、[Feedly 的去重与事件聚类](https://feedly.com/engineering/posts/reducing-clustering-latency)、[TrendRadar](https://github.com/sansan0/TrendRadar)。本实现保留现有 Node.js / SQLite / Tauri 架构。
