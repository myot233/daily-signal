# 设置的产品逻辑

Daily Signal 是本地 RSS 阅读与 AI 日报工具。设置围绕“什么时候更新、什么时候生成、用什么模型”组织；“关心什么、日报怎么写”继续在日报设置中编辑。

| 入口                | 内容                             | 生效范围                         |
| ------------------- | -------------------------------- | -------------------------------- |
| 设置 → 通用设置     | 订阅刷新频率、自动日报开关和时间 | 当前本地应用的后台任务           |
| 设置 → 模型与服务商 | 连接、Key、模型、默认模型        | 下次模型调用                     |
| 日报设置            | 兴趣标签、精选规则、写作模板     | 下次日报生成，已归档内容保持原样 |

## 通用设置

订阅自动刷新默认关闭，可选择 15 分钟、30 分钟、1 小时、2 小时或 4 小时。保存后从下一周期执行，启动应用不会立刻批量访问订阅站点；没有订阅时跳过。自动任务与手动刷新、OPML 导入共享抓取队列，已有任务运行时跳过当前周期，下一周期再试。现有并发、网络安全、失败保留和进度展示规则继续适用。

每日自动生成沿用已有本地时间调度器，默认关闭，默认时间为 20:00。启用前需要已启用、保存了 Key 的默认模型，前后端均检查这一条件。生成使用已保存的兴趣筛选和模板，以及已经抓取的当天文章；当天已有归档或另一份日报正在生成时跳过。修改时间、关闭任务均在保存后生效。

这些任务只在本地后端运行期间执行。关闭应用期间的任务不补跑，不把本地定时任务包装为系统级后台服务。Web 页面关闭但本地服务仍在运行时，任务继续执行。

## 保存与草稿

通用设置统一保存。修改后显示未保存状态，放弃修改回到最近一次保存值；保存失败保留草稿。在应用内切换至模型配置再返回时，草稿仍在，方便先补齐模型条件；关闭或刷新页面时提示未保存修改。未保存值不改变后台任务。

模型和模板沿用各自的保存流程。通用设置只提交自动任务字段，服务端合并到当前保存值，不接受模型地址、Key、模板或兴趣规则。旧版完整设置接口仍兼容现有日报内容编辑。

## 实现边界

- `/settings` 展示通用设置；`/settings/providers` 与 `/settings/providers/:providerId` 展示已有模型管理。阅读和生成时的模型配置快捷入口直接到模型管理。
- `settings.saveAutomation` 使用严格契约，只接受 `autoDigest` 和 `feedRefresh`，返回公共设置。输入无效或模型条件不足时，已保存设置保持不变。
- `feedRefresh.intervalMinutes` 存在现有设置 JSON 内，旧库读取时补上关闭值，无需 SQL 结构迁移；已有自动日报时间保持原样。
- `packages/api/src/feed-refresh-scheduler.ts` 负责跨领域刷新编排，复用订阅队列。频率未变化时保留当前周期；服务退出时停止定时器。
- 开启自动刷新后，页面每 10 秒查询轻量抓取状态，任务运行时每秒查询；完整文章数据继续沿用节流刷新。

回归覆盖包括旧库默认值、设置持久化、Key 与模板隔离、无默认模型时保存刷新频率、非法输入拒绝、定时任务互斥、关闭任务、保存失败和跨页面草稿保留。
